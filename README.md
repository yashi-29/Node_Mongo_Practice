# Node.js MongoDB CRUD App

A simple full-stack CRUD web application built with Node.js, Express, MongoDB, Mongoose, EJS, and session-based authentication.

Users can register with an email and password, stay logged in for 30 days, and manage their own private item list. Each user's items are isolated, so one account cannot view, edit, or delete another account's data.

## Features

- User registration with email and password
- User login and logout
- Persistent login for 30 days unless the user logs out
- MongoDB-backed sessions using `connect-mongo`
- Passwords stored as salted hashes, not plain text
- Create, read, update, and delete items
- Per-user item isolation
- Server-side validation with Mongoose
- EJS-based frontend views
- Basic responsive styling

MongoDB should be running before starting the app.

## Installation

Open PowerShell in the project folder:

```powershell
cd "C:\Users\USER\\Documents\node & mongo"
```

Install dependencies:

```powershell
npm install
```

## Environment Variables

Create a `.env` file in the project root.

Example:

```env
PORT=3001
MONGODB_URI=mongodb://127.0.0.1:27017/simple_crud_app
SESSION_SECRET=replace-this-with-any-random-secret
```

`SESSION_SECRET` is used to sign login sessions. Use a strong random value for real projects.

## Running the App

Start the development server:

```powershell
npm run dev
```

The terminal should show:

```text
Connected to MongoDB
Server running at http://localhost:3001
```

Open the app:

```text
http://localhost:3001
```

## How to Use

1. Open `http://localhost:3001`.
2. Click `Create an account`.
3. Register with your email and password.
4. After registration, you will be redirected to the Item Manager page.
5. Add, edit, or delete your own items.
6. Click `Logout` only when you want to end your login session.

If you close the browser and open the app again, you should go directly to the Item Manager page as long as:

- You did not click logout
- The 30-day session has not expired
- Browser cookies were not cleared
- MongoDB session data was not deleted

## Authentication Flow

```text
Register/Login
  |
  v
Session saved in MongoDB
  |
  v

  |
  v
User can access /items
  |
  v

```

## Main Routes

| Method | Route | Description |
| --- | --- | --- |
| GET | `/` | Redirects to login or items page |
| GET | `/register` | Shows registration page |
| POST | `/register` | Creates a new user account |
| GET | `/login` | Shows login page |
| POST | `/login` | Logs in an existing user |
| POST | `/logout` | Logs out the current user |
| GET | `/items` | Shows the logged-in user's items |
| POST | `/items` | Creates a new item |
| GET | `/items/:id/edit` | Shows edit page for one item |
| PUT | `/items/:id` | Updates one item |
| DELETE | `/items/:id` | Deletes one item |

## Data Models

### User

The `User` model stores account information:

- `email`
- `passwordHash`
- `salt`
- `createdAt`
- `updatedAt`

### Item

The `Item` model stores item information:

- `name`
- `description`
- `age`
- `owner`
- `createdAt`
- `updatedAt`

The `owner` field connects each item to the user who created it.

## Notes

- `node_modules` is not committed because it is generated by `npm install`.
- `.env` should not be committed because it contains local configuration.
- `package-lock.json` should be committed because it keeps dependency versions consistent.
